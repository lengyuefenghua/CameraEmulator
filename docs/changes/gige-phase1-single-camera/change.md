## 需求卡
目标：每次启动所选虚拟相机时，软件以 Wintun 创建一张专属 L3 虚拟适配器，使 MVS 主机端与相机端使用同网段的不同 IPv4 地址，并可发现、连接和连续取图；停止相机即销毁该适配器。

验收标准：
1. 点击“启动所选”后，程序请求所需管理员权限，创建仅属于当前相机的 Wintun 适配器，配置主机侧 IPv4，并在该适配器上运行相机端 IPv4。
2. MVS 使用该适配器发现相机、读取程序生成的兼容 GenICam XML、连接并连续取得完整图像；适配器有可观察的收发流量。
3. 同一时刻仅运行一台相机；切换所选档案时，旧流和旧适配器先停止并销毁，再创建并启动新相机的适配器。
4. 停止相机、退出程序或启动失败时，释放 Wintun 会话并删除本次创建的适配器；不会删除用户已有的适配器。
5. 适配器创建、主机地址配置、Wintun 收发、GVCP/GVSP 解析或销毁失败时，界面和日志给出相机标识、适配器名与系统错误；不静默回退到用户现有 WLAN/VPN/WireGuard 适配器。
6. 保持现有 EXE 同级 `virtual-cameras/*.json` 选择、绝对 BMP 源和目录循环播放；JSON 的相机 IP 表示隧道内远端相机地址，不要求该地址被 Windows 本机接口绑定。

非目标：复用或管理用户已有适配器、多相机同时运行、IPv6、二层以太网帧仿真、第三方厂商 XML、跨进程服务、Linux。

## 协作卡（类图形）
边界：单一提升权限的 Windows 进程；Windows IP 栈/MVS 是 Wintun 主机端，相机端仅在用户态 L3 peer 中存在。
图例：[增]=新增　[改]=修改　[有]=既有复用（不动）　──▶=调用方向

[改] Qt 主窗口（MainWindow）──启动所选──▶[改] 引擎门面（EngineFacade）──切换（CameraConfig）→成功/错误──▶[改] 相机实例（CameraInstance）
[改] 相机实例──创建/停止 peer──▶[增] Wintun peer（WintunPeer）──IPv4/UDP──▶[有] GVCP 分发器（GvcpDispatcher）
[改] 相机实例──兼容 XML──▶[增] 隧道 HTTP（TunnelHttpServer）──IPv4/TCP──▶ MVS
[改] 流发送器（StreamController）──GVSP UDP──▶[增] Wintun peer──IPv4──▶ MVS
[增] Wintun peer──适配器 LUID/主机地址/相机端 /32 路由──▶ Windows IP Helper / Wintun.dll

共享接口：引擎门面 `切换相机（CameraConfig）→成功/错误` 是 GUI 唯一启动入口；Wintun peer `启动（相机配置）→主机端地址/错误` 是相机网络唯一入口；peer `发送 IPv4（报文）→成功/错误` 是 GVCP、GVSP、隧道 HTTP 唯一出站路径。
改动边界：新增＝Wintun peer、IPv4/UDP 编解码和隧道 HTTP；修改＝相机实例、流发送器、引擎门面、GUI/打包；复用不动＝RegisterMap、GenICam 生成、GVCP/GVSP 编解码、配置档案库与图像序列。
不变量：JSON 相机 IP 仅为远端相机端；主机端地址自动从同一子网导出并与相机端不同；适配器带仅指向相机端的 /32 路由；相机端不经 Windows Winsock bind；任何时刻仅有本程序创建的一张适配器；第三方 XML 不被读取或分发。
禁止形状：回退到用户已有适配器、用相同 IP 冒充两个端点、用现有 UDP socket 绕过 peer、将 Wintun 作为二层以太网帧设备。
偏离定义：只处理 IPv4 的 UDP（GVCP/GVSP）及为 XML 提供完整握手、确认、响应、关闭、超时的最小 HTTP/TCP 会话；非目标协议包丢弃并记录限流 WARN。

## 流程契约
触发：GUI 启动所选、停止、切换所选或进程退出（等价停止）。
入口参数：启动/切换均传入完整 CameraConfig；相机端使用 JSON IP，主机端从相同子网的首个可用主机地址导出，若与相机端、本机地址或既有路由冲突则启动拒绝；同时安装仅指向相机端的 /32 路由。
启动所选 ─┐
切换所选 ─┼→ 停止旧流/结束会话/删除旧路由与适配器 → 请求提升权限 → 创建专属 Wintun 适配器 → 配置主机端 IPv4 与相机端 /32 路由 → 启动 L3 peer（相机端 IPv4）→ 从 peer 收取 IPv4 → UDP 3956 分发 GVCP / 最小 TCP 状态机 HTTP 返回兼容 XML → AcquisitionStart 后经 peer 发送 GVSP → 更新状态与诊断
进程退出 ─┴→ 停止流/结束会话/删除本次适配器
返回：成功 = UI 显示适配器名、主机端/相机端地址并可由 MVS 发现、读取 XML、取流；失败 = 停止状态且显示创建、地址配置、协议或销毁原因。
异常线：
- 提升/创建/地址或相机端 /32 路由配置 → ERROR，撤销已创建资源，不产文件、不使用既有适配器。
- peer 收到损坏、IPv6 或非目标报文 → 限流 WARN 丢弃，不中断会话。
- GVCP/GVSP/隧道 TCP HTTP 的握手、确认、超时或关闭失败 → ERROR，记录相机标识、端点与系统/协议错误；当前会话可继续时不中断。
- 停止/退出删除失败 → ERROR，保留错误诊断；只尝试删除本次创建的适配器。

## 影响
- 能力：新增 `wintun-l3-peer`、`tunnel-http-xml`；修改 `gvcp-control`、`gvsp-streaming`、`camera-gui`。
- Data：JSON 结构不变；其 IP 语义改为隧道远端相机端地址，主机端地址运行时导出。
- Risks：最小 TCP/HTTP 实现必须兼容 MVS XML 获取；Wintun/IP 配置依赖提升权限；启动失败或异常退出时需可靠清理唯一创建的适配器。
